# Final Project Rubric — 100 Points

| Area | Points | Full-credit evidence |
|---|---:|---|
| Python fundamentals | 10 | Correct values, types, expressions, naming, and formatting |
| Control flow | 10 | Clear rules and correct happy/failure/boundary paths |
| Functions and modularity | 10 | Focused reusable functions; imports and layers are coherent |
| Data structures | 10 | Appropriate collections and reliable search/result handling |
| Object-oriented programming | 15 | Purposeful repository/service/email classes; composition and encapsulation are explainable |
| Database / CRUD | 15 | SQLite initializes; create/read/update/delete persist correctly; SQL stays out of routes |
| FastAPI | 15 | HTML and required JSON routes work with correct status codes/templates |
| Validation / error handling | 5 | Required fields, email, duplicates, missing users, and failures are handled |
| Email functionality | 5 | Environment-based SMTP and safe local fallback both exist; result is logged |
| Code quality / documentation | 5 | Readable PEP 8-style code, no secrets, accurate setup and useful UX |
| **Total** | **100** | |

## Performance bands

- 90–100: complete, reliable, readable, and independently explainable.
- 80–89: core workflows work; small correctness or clarity gaps remain.
- 70–79: partial integration with one material workflow or architecture gap.
- Below 70: multiple required workflows fail or implementation cannot be explained.

Evaluate real behavior, readability, modularity, correct Python, user experience, and error handling. Award partial credit by the proportion of observable criteria met; visual polish cannot replace correctness.
